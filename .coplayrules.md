
# Coplay Rules

## 🌐 **NGÔN NGỮ & GIAO TIẾP**
- Sử dụng tiếng Việt để trả lời
- Không sửa code khi tôi yêu cầu đưa ra đề xuất hay làm tài liệu
- Không tạo tài liệu khi không được yêu cầu

## 📁 **QUY TẮC QUẢN LÝ FILE & CODE**
1. **Không tạo file trùng lặp:** Luôn sử dụng và cải thiện các file/script hiện có thay vì tạo mới
2. **Sửa chữa trên file cũ:** Hoàn thiện chức năng bằng cách modify code existing
3. **Chỉ tạo script mới khi:**
   • Bạn yêu cầu tạo logic hoàn toàn mới
   • Cần implement một cách tiếp cận mới
   • Được yêu cầu tạo component/system mới
4. **Ưu tiên sửa lỗi:** Khi có lỗi, sẽ cố gắng fix thay vì xóa file
5. **Sử dụng Unity 6.2 standards:** Code và Input System phù hợp với Unity 6.2

## 🎨 **UI MANIPULATION RULES**

### **TUYỆT ĐỐI KHÔNG TẠO SCRIPT CHO CÁC THAO TÁC UI ĐỚN GIẢN**
- ❌ **KHÔNG tạo script để disable/enable GameObject**
- ❌ **KHÔNG tạo script để set active/inactive UI elements**
- ❌ **KHÔNG tạo script để thay đổi vị trí, kích thước UI đơn giản**
- ❌ **KHÔNG tạo script để assign references có thể làm thủ công**

### **CHỈ SỬ DỤNG UNITY EDITOR TOOLS:**
- ✅ **Sử dụng Inspector để disable/enable GameObjects**
- ✅ **Sử dụng RectTransform để điều chỉnh UI positioning**
- ✅ **Sử dụng drag & drop để assign references**
- ✅ **Sử dụng Unity tools để thao tác với UI elements**

### **CHỈ TẠO SCRIPT KHI:**
- ✅ **Cần logic phức tạp (animations, conditional behaviors)**
- ✅ **Cần runtime functionality (button click handlers, data binding)**
- ✅ **Cần integration với game systems**
- ✅ **Được yêu cầu tạo custom UI components**

### **EXAMPLES CỤ THỂ:**

#### **❌ KHÔNG LÀM:**
```csharp
// KHÔNG tạo script chỉ để disable UI
public class DisablePanel {
    public static void Execute() {
        GameObject.Find("Panel").SetActive(false);
    }
}
```

#### **✅ LÀM:**
- Chọn GameObject trong Hierarchy
- Uncheck checkbox bên cạnh tên GameObject trong Inspector
- Hoặc sử dụng Unity Editor tools

## 🎯 **UNITY PROJECT ERROR FIXING RULES**

### **NHIỆM VỤ CHÍNH**
Khi xử lý lỗi Unity project: **CHỈ SỬA LỖI** mà **KHÔNG THAY ĐỔI LOGIC HIỆN TẠI**.

### **🚫 CÁC QUY TẮC BẢO VỆ NGHIÊM NGẶT**

#### **TUYỆT ĐỐI KHÔNG ĐƯỢC LÀM:**
- ❌ **Xóa hoặc disable các script đang attach vào GameObjects trong scene**
- ❌ **Thay đổi tên class, method, hoặc public variables đang được reference**
- ❌ **Move, rename, hoặc delete các script files đang được sử dụng**
- ❌ **Refactor hoặc optimize code logic đang hoạt động**
- ❌ **Thay đổi workflow hiện tại (UI buttons, character selection, spawning)**
- ❌ **Tự động thực hiện changes lớn mà không hỏi permission**

#### **CHỈ ĐƯỢC PHÉP LÀM:**
- ✅ **Fix compile errors (CS0103, CS0246, CS8618, etc.)**
- ✅ **Fix runtime errors và exceptions**
- ✅ **Fix warnings không ảnh hưởng đến functionality**
- ✅ **Add missing using statements**
- ✅ **Fix null reference assignments**
- ✅ **Comment out problematic code thay vì xóa**

## 📋 **EXAMPLES CỤ THỂ**

### **✅ ĐƯỢC PHÉP:**
```csharp
// Fix compile error CS0103
// TRƯỚC:
gameStateManager.StartGame(); // Error: gameStateManager không tồn tại

// SAU:
// gameStateManager.StartGame(); // DISABLED FOR CLEANUP - Fix compile error
```

```csharp
// Fix null reference warning CS8618
// TRƯỚC:
public Button resetButton;

// SAU:
public Button? resetButton; // hoặc
// public Button resetButton; // DISABLED FOR CLEANUP
```

### **❌ KHÔNG ĐƯỢC PHÉP:**
```csharp
// KHÔNG được thay đổi tên method đang được gọi
// TRƯỚC:
public void StartBattle() { ... }

// SAU - KHÔNG ĐƯỢC LÀM:
public void InitiateBattle() { ... } // ❌ Thay đổi tên method
```

```csharp
// KHÔNG được xóa script đang được sử dụng
// ❌ KHÔNG ĐƯỢC LÀM:
remove-files ["Assets/Scripts/CleanUIManager.cs"] // Script đang attach vào GameObject
```

## 🔍 **QUY TRÌNH XỬ LÝ**

### **BƯỚC 1: PHÂN TÍCH**
1. Đọc error messages từ Unity Console
2. Xác định loại lỗi: compile error, runtime error, hay warning
3. Kiểm tra xem script có đang được sử dụng trong scene không

### **BƯỚC 2: FIX STRATEGY**
1. **Compile Errors:** Comment out thay vì xóa code
2. **Missing References:** Add null checks hoặc comment out
3. **Deprecated Methods:** Thêm pragma để suppress warnings
4. **Type Errors:** Fix type declarations mà không thay đổi logic

### **BƯỚC 3: VERIFICATION**
1. Compile thành công
2. Test existing functionality (UI buttons, character selection)
3. Đảm bảo không có regression
